# eval/ — стенд для замера качества ответов

Качество RAG нельзя оценивать на глаз: «вроде отвечает» — не метрика. Здесь лежит воспроизводимый замер, на котором проверяется каждое изменение в поиске.

## Как устроен замер

**Датасет** строится из настоящих тредов: берётся тред, где человек задал вопрос и получил ответ от участников чата. Модель переформулирует вопрос своими словами (иначе поиск нашёл бы тред по дословному совпадению и замер ничего бы не показал) и выписывает из обсуждения ключевые факты — эталон.

Каждый случай: `вопрос` → `тред-источник` (правильный ответ поиска) → `gold_points` (что обязан содержать хороший ответ).

**Метрики:**

| Метрика | Что показывает |
|---|---|
| `recall@5`, `recall@15` | нашёлся ли нужный тред в топ-5 / топ-15 |
| `mrr` | насколько высоко он стоит в выдаче |
| `answer_score` | оценка ответа экзаменатором, 0–5 |
| `fact_coverage` | доля эталонных фактов, попавших в ответ |
| `hallucinations` | ответы с выдуманной конкретикой |

Экзаменатор — отдельная LLM, которая видит эталонные факты и ответ бота, но не видит конфигурацию поиска.

## Запуск

```bash
python eval/build_dataset.py       # собрать датасет из тредов
python eval/index_corpus.py        # проиндексировать корпус
python eval/evalrun.py --name baseline --vector
python eval/evalrun.py --name hybrid --vector --fts
python eval/evalrun.py --name reranked --vector --fts --rerank
```

Флаги включают ступени поиска: `--vector` векторный, `--fts` полнотекстовый, `--rerank` реранкер, `--rewrite` переформулировка запроса, `--recency` вес свежести. Результат раунда — в `eval_<name>.json`.

## Данные

Сам датасет (`dataset.json`) в репозиторий не попадает: он собран из приватной переписки реальных людей. В репозитории — только код замера и агрегированные результаты.
