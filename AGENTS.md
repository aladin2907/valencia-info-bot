# valencia_info_bot — локальные инструкции

Перед работой прочитай общий канон [`~/knowledge/AGENTS.md`](~/knowledge/AGENTS.md), включая startup, два вида тестов и write-back. Здесь — только специфика проекта; общие правила не копировать.

## О проекте

RAG-бот о жизни в Валенсии: отвечает на вопросы по обсуждениям из русско- и украиноязычных Telegram-групп экспатов. Telegram-бот и будущее мобильное приложение — клиенты одного `POST /ask`; поиск на своих моделях (bge-m3 + bge-reranker-v2-m3), база Postgres + pgvector, ответы через OpenAI. Код готов и проверен локально; боевой токен пока на n8n, AWS-стек (ECS, devops Олексія) ждёт сетевых интерфейсов под бота. Текущее — `knowledge/state.md`.

## Структура и знания

Проект: `valencia-info-bot`. Код и рабочие артефакты — в корне/рабочих каталогах; вся вика — `knowledge/`. Структура вики и назначение state/log/backlog/escalations/incidents описаны в общем каноне.

Каталоги кода:

- `app/` — FastAPI-сервис ответов (`POST /ask`, `/health`), конфиг, поиск, вызов LLM.
- `bot/` — Telegram-бот (aiogram, опрос; проверяет чужой webhook при старте).
- `ingest/` — ночной сбор: Telethon-докачка, сборка тредов, векторы.
- `models/` — сервис эмбеддингов и реранкера (свой образ).
- `sql/` — схема и гибридный поиск; `scripts/` — накат схемы, загрузка тредов из файлов.
- `eval/` — замер качества на 50 вопросах; `docs/` — ARCHITECTURE, QUALITY, DEPLOY.
- `data/`, `sessions/`, `.env` — приватное, в git не попадает. `legacy/`, `reference/n8n/` — старый n8n-бот как спецификация.

## Категории

- `integrations/` — AWS (ECS, планировщик базы), Telegram и n8n (webhook, сбор через Telethon), OpenAI.
- `decisions/` — решения владельца по поиску, моделям, инфраструктуре; спеки по циклу разработки.
- `experiments/` — новые замеры качества (исторические — в `docs/QUALITY.md` репозитория).

## Границы автономии

- **Свободно:** создавать/обновлять страницы в knowledge/, log, state и index.
- **С подтверждением:** изменения кода проекта, новые категории knowledge/, удаление страниц. Явное разрешение владельца в текущей задаче уже считается подтверждением.
- **Никогда:** менять raw/, push без команды, удалять чужие файлы вне knowledge/.

Проектные границы:

- Секреты (`.env`, `sessions/`, id приватных групп, ключи Telegram/OpenAI/AWS) не выводить в чат, не коммитить, не копировать между проектами без владельца.
- `data/` — приватная переписка живых людей: не публиковать, не пересылать во внешние сервисы, кроме LLM-вызовов самого бота.
- Токен `@valencia_info_bot`: снимать чужой webhook (`ALLOW_WEBHOOK_TAKEOVER=1`) только по явному решению владельца — это переключение боевого бота.
- AWS: Terraform и ECS ведёт devops (Олексій); мы меняем образы и настройки, не инфраструктуру. Вход `aws sso login` делает владелец.
- Полный корпус (20 633 треда) и замер на 50 вопросах — часы CPU: запускать по согласованию, не «для проверки».
